# 2026-08-28 로그 분석 Ubuntu와 그룹 권한

출처: ktcloud-infra-강의노트1.docx의 8/28 기록. VM 가져오기 절차와 비밀번호는 제외했다.

## awk 사용자 정보 추출

```bash
awk -F: '$3 >= 1000 && $3 <= 60000 {print $1, $3}' /etc/passwd | column -t
```

콜론 구분 필드 중 3번째 UID를 조건으로 로그인 이름과 UID를 출력한다. 1000~60000은 이 예시의 범위이지 모든 시스템에서 일반 사용자를 완벽하게 구분하는 보편 규칙은 아니다.

## 웹 로그 집계

```bash
awk '{print $1}' access.log | sort | uniq -c | sort -nr
awk '{print $9}' access.log | sort | uniq -c | sort -nr
```

첫 번째는 접속 IP별, 두 번째는 예시 로그 형식에서 HTTP 상태 코드별 개수를 구한다. 원문에서 200은 7건, 404는 2건이었다. 빈 행도 1건 집계되었으므로 필요하면 `awk 'NF {print $1}'`처럼 빈 행을 제외한다.

## Ubuntu 원격 접속과 호스트 이름

```bash
ip addr
ping google.com
hostname
sudo hostnamectl hostname ubuntu
cat /etc/hostname
```

당시 Ubuntu 주소를 확인하고 Rocky에서 SSH로 접속했다. 이미지에는 당시 Ubuntu `192.168.120.128`이 보이므로 9.11의 .129와 혼동하지 않는다. 사용자 비밀번호 변경 기록도 있지만 실제 값은 수록하지 않는다.

## umask

`umask 0000`과 `umask 0022`에서 mkdir/touch로 만든 권한을 비교했다. 기본 생성 요청 권한에서 umask 비트를 제거하므로 일반적인 파일과 디렉터리의 최종 권한은 다르다.

## Docker 그룹

```bash
# root
usermod -aG docker student
id student
# student 세션
newgrp docker
id
docker ps
```

그룹 데이터 변경과 기존 세션의 그룹 반영은 별개다. newgrp 후 docker 그룹을 사용하는 새 셸에서 docker ps 실행을 확인했다. Docker 그룹은 데몬을 제어하는 강한 권한이므로 단순 조회 전용 그룹으로 이해하지 않는다.

Ubuntu·Rocky 버전 비교표와 VirtualBox 네트워크 모드 비교 자료도 포함되어 있다. 해당 표는 당시 강의 자료이며 현재 지원 정책을 검증한 목록은 아니다.
