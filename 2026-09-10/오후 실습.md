## 네트워크 상태 확인

mynet 생성 전에 실행한 명령:

```bash
ip r
ping google.com
cat /etc/resolv.conf
ip a s ens160
ip -s link show ens160
ip -6 r
man nmcli-examples
nmcli dev status
nmcli con show ens160
```

확인 결과:

- 기본 경로: `default via 192.168.120.2 dev ens160 proto static metric 100`.
- 직접 연결 경로: `10.0.0.0/24`, `192.168.120.0/24`, docker0의 `172.17.0.0/16`(linkdown).
- DNS: NetworkManager가 생성한 resolv.conf에 `search localdomain`, `nameserver 192.168.120.2`.
- ens160에 기존 주소와 임시 주소 `10.0.0.10/24`가 함께 존재.
- google.com ping: 2개 전송·2개 수신, 손실률 0%.
- 링크 통계: RX errors 0, TX errors 0, TX dropped 3. 이 수치만으로 원인을 단정하지 않음.
- IPv6 경로: `fe80::/64 dev ens160`.

`nmcli con`과 `nmcli con show`는 연결 프로필 목록을 보여준다. DEVICE는 실제 장치, CONNECTION/NAME은 프로필 이름이다. 강사 환경의 `유선 연결 1`과 본인 환경의 `ens160`은 이름만 다를 수 있다. `cho`가 아니라 `show`이며 `sho`로 줄일 수 있다.

## IP 변경: Rocky NetworkManager

### 1. 고정 IP 프로필 생성

```bash
nmcli con add con-name mynet type ethernet ifname ens160 ip4 192.168.120.128/24 gw4 192.168.120.2 ipv4.dns 192.168.120.2 ipv4.method manual
```

- `con-name mynet`: 새 프로필 이름.
- `type ethernet`, `ifname ens160`: 유선 장치 ens160에 적용할 설정.
- `ip4`: 주소와 프리픽스, `gw4`: 기본 게이트웨이.
- `ipv4.dns`: DNS 서버, `ipv4.method manual`: 수동 주소 설정.

생성 성공 후 mynet의 DEVICE는 `--`로 표시되었다. 생성만으로 활성화되는 것은 아니다.

### 2. 활성화 및 외부 통신 확인

```bash
nmcli con show
nmcli dev status
nmcli con up mynet
nmcli con show
ip -br addr
ping google.com
```

- 활성 프로필이 ens160에서 mynet으로 변경.
- 기존 ens160 프로필은 삭제되지 않고 DEVICE `--`로 남음.
- 주소 `192.168.120.128/24` 확인. 이전 임시 주소 `10.0.0.10/24`는 이때 출력에서 사라짐.
- google.com ping 5개 전송·5개 수신, 손실률 0%로 DNS 조회 및 외부 통신 확인.

### 3. 저장된 설정 파일 확인

```bash
cd /etc/NetworkManager/system-connections
cat mynet.nmconnection
```

핵심 설정:

```ini
[connection]
id=mynet
type=ethernet
interface-name=ens160

[ethernet]

[ipv4]
address1=192.168.120.128/24
dns=192.168.120.2;
gateway=192.168.120.2
method=manual

[ipv6]
addr-gen-mode=default
method=auto
```

실제 파일에는 UUID도 포함된다. 파일에 저장된 영구 프로필이지만 부팅 시 선택되는 프로필은 자동 연결 설정·우선순위 등의 영향을 받는다.

### 4. 추가 IP를 영구 프로필에 등록

```bash
nmcli con mod mynet +ipv4.addresses 10.0.0.10/24
nmcli con up mynet
ip -br a
ping 10.0.0.11
```

`+ipv4.addresses`는 기존 주소를 유지하면서 추가한다. ens160에 두 IPv4 주소가 표시되었고 Ubuntu ping은 3개 전송·3개 수신, 손실률 0%였다.

```bash
cd -
cat mynet.nmconnection
```

`cd -`는 직전 디렉터리로 이동한다. 파일의 `[ipv4]`에 다음 항목이 추가된 것을 확인했다.

```ini
address2=10.0.0.10/24
```

### 5. 파일 직접 편집으로 세 번째 IP 적용

```bash
cd /etc/NetworkManager/system-connections
vi mynet.nmconnection
cd
nmcli con reload mynet
nmcli con up mynet
ip -br addr
```

위는 제출된 실행 로그다. 편집한 파일 본문은 제공되지 않았지만 결과에서 `192.168.120.128/24`, `10.0.0.10/24`, `172.16.0.10/24` 세 주소를 확인했다.

전체 연결 파일을 다시 읽는 표준 형태로는 다음을 안내했다.

```bash
nmcli con reload
nmcli con up mynet
```

`ip addr add`는 일시적 설정, `nmcli con mod`는 저장된 프로필 변경이라는 차이가 있다.

## 라우팅 실습

### 1. Ubuntu의 기존 주소 삭제

Ubuntu root에서:

```bash
ip addr del 192.168.120.129/24 dev ens160
```

장치를 끄는 것이 아니라 주소 하나를 제거한다. Rocky에서 확인:

```bash
ping 10.0.0.11
# 2개 전송·2개 수신, 손실률 0%
ping 192.168.120.129
# 18개 전송·0개 수신, 대상 호스트에 도달할 수 없음
```

### 2. Windows에 정적 경로 추가

시작 버튼 우클릭 → 터미널(관리자), 또는 PowerShell 검색 → 관리자 권한으로 실행.

```powershell
route ADD 10.0.0.0 MASK 255.255.255.0 192.168.120.128 METRIC 3 IF 6
ping 10.0.0.11
```

| 인수 | 의미 |
|---|---|
| 10.0.0.0 MASK 255.255.255.0 | 목적지 10.0.0.0/24 |
| 192.168.120.128 | 다음 홉 Rocky |
| METRIC 3 | 경로 비용 지정 |
| IF 6 | Windows의 VMnet8 인터페이스 번호 |

VMnet8의 주소 192.168.120.1은 다음 홉 Rocky와 같은 /24 대역이므로 해당 인터페이스를 사용한다. VMnet8의 8과 IF 6의 6은 서로 다른 번호 체계다. ipconfig의 링크 로컬 IPv6 끝 `%6`은 인터페이스 구분 값이며 route에는 `%` 없이 `IF 6`으로 입력했다. 다른 PC에서는 번호가 다를 수 있다. 이 명령에는 영구 저장 옵션 `-p`가 없다.

### 3. 실패 원인과 Ubuntu 반환 경로 수정

Windows에서 처음 ping은 요청 시간 초과였다. Ubuntu에서 확인:

```bash
ip route get 192.168.120.1
```

수정 전:

```text
192.168.120.1 via 192.168.120.2 dev ens160 src 10.0.0.11
```

응답을 실습 라우터 Rocky가 아니라 기존 게이트웨이 .2로 보내려는 상태였다. 다음으로 Windows 대역의 반환 경로를 추가했다.

```bash
ip route add 192.168.120.0/24 via 10.0.0.10 dev ens160
ip route get 192.168.120.1
```

수정 후:

```text
192.168.120.1 via 10.0.0.10 dev ens160 src 10.0.0.11
```

사용자가 통신 성공을 확인했고, Windows 화면에서도 4개 전송·4개 수신, 손실률 0%가 표시되었다.

### 4. Rocky가 라우터 역할을 하는 원리

```text
Windows 192.168.120.1
  → Rocky 192.168.120.128 / 10.0.0.10
  → Ubuntu 10.0.0.11
  → Rocky 10.0.0.10 / 192.168.120.128
  → Windows 192.168.120.1
```

Windows에는 가는 경로, Ubuntu에는 돌아오는 경로가 필요하다. Rocky는 `net.ipv4.ip_forward=1`이면 자신의 주소가 목적지가 아닌 패킷을 중계할 수 있다. 방화벽의 전달 허용도 필요하다. 같은 ens160에 두 대역을 설정했으므로 같은 인터페이스로 받아 다시 내보내는 구성이다.

진단용으로 안내한 명령(실행 출력은 제공되지 않음):

```bash
sysctl net.ipv4.ip_forward
# 0인 경우 실습용으로 활성화
sysctl -w net.ipv4.ip_forward=1
```

Rocky 자체에서 Ubuntu로 ping이 되는 것만으로 중계 기능까지 검증되는 것은 아니다.

### 5. Ubuntu 주소 복구와 오타

기존 주소 삭제 상태에서 Rocky → Ubuntu SSH는 다음처럼 사용할 수 있다.

```bash
ssh student@10.0.0.11
```

원래 주소 복구 명령:

```bash
ip addr add 192.168.120.129/24 dev ens160
```

화면에 `192.168.102.129/24`를 입력한 오타가 있었다. Enter 전이면 102를 120으로 고치고, 이미 실행했다면 잘못된 주소를 삭제한 후 올바른 주소를 추가하도록 안내했다.

```bash
ip addr del 192.168.102.129/24 dev ens160
ip addr add 192.168.120.129/24 dev ens160
ip -br addr
```

위 정정 명령의 실행 결과는 제공되지 않았다. 기존 주소 복구 시 Ubuntu는 Windows와 같은 대역이 되어 반환 경로가 직접 연결로 바뀔 수 있다.
Windows ping 화면의 TTL은 63에서 64로 바뀌었다. 초기 TTL 64를 가정하면 응답의 중간 라우터 수가 달라진 상황과 맞지만, TTL만으로 경로를 확정할 수 없다.

## 소켓과 서비스 확인

```bash
ss -nlp | grep ssh
ss -nltp | grep ssh
netstat -a | grep http
netstat -a | grep ssh
```

- `n`: 숫자 표시, `l`: 수신 대기, `t`: TCP, `p`: 프로세스 표시.
- TCP 필터가 없으면 UNIX 소켓도 표시된다.
- 당시 sshd는 IPv4 `0.0.0.0:22`, IPv6 `[::]:22`에서 LISTEN.
- keyring/ssh 및 ssh-unix-local/socket은 UNIX 소켓.
- `netstat -a | grep http`에 나온 cgisock은 TCP 웹 포트가 아닌 로컬 UNIX 소켓이다.
- HTTP 82 확인용으로 `ss -nltp | grep ':82'`를 안내했다.

## IP 변경: Ubuntu Netplan

제출된 명령:

```bash
vi /etc/netplan
vi 50-cloud-init.yaml
netplan apply
```

`/etc/netplan`은 디렉터리다. 홈에서 상대 경로로 파일을 열면 적용 대상 경로와 달라질 수 있어 전체 경로를 안내했다.

```bash
vi /etc/netplan/50-cloud-init.yaml
```

화면의 `ethernet:`과 `address:` 오타를 각각 `ethernets:`와 `addresses:`로 수정하도록 안내했다.

```yaml
network:
  version: 2
  ethernets:
    ens160:
      dhcp4: false
      addresses: [192.168.120.129/24]
      nameservers:
        addresses: [192.168.120.2, 8.8.8.8]
      routes:
        - to: default
          via: 192.168.120.2
```

검사·적용·확인용 안내 명령:

```bash
netplan generate
netplan apply
ip -br addr
ip route
```

들여쓰기는 스페이스 사용. 이 구성은 10.0.0.11을 포함하지 않는다. 수정 후 검증 출력이 없으므로 Netplan 적용 성공은 미확인이다.

## SSH 포트 및 공개키 실습

### 1. Rocky root의 RSA 키 생성

```bash
ssh-keygen -t rsa
ls ~/.ssh/*
cat ~/.ssh/id_rsa.pub
```

RSA 3072비트 키 생성 성공. 개인키 `/root/.ssh/id_rsa`, 공개키 `/root/.ssh/id_rsa.pub`가 생성되었다. 키 암호 설정 여부는 입력 기록으로 판단할 수 없다.
기본 RSA 파일과 Ed25519의 `id_ed25519`는 이름이 다르다. 다른 키를 덮어쓰거나 SSH 선택 설정을 변경하지 않는 한 생성 자체로 GitHub 등록 정보는 바뀌지 않는다. Rocky root의 키는 Windows·다른 사용자 홈의 키와 별개다.

`/etc/ssh`에서 확인한 `ssh_host_rsa_key`, `ssh_host_ecdsa_key`, `ssh_host_ed25519_key`는 서버 신원용 호스트 키다. 사용자 인증용 `~/.ssh/id_rsa`와 구분한다. `.pub`는 공개키다.

### 2. Rocky root → Ubuntu student 공개키 등록

처음 Ubuntu student에서 `ssh-copy-id student@192.168.120.129`를 실행해 `No identities found` 발생. 키를 만든 계정은 Rocky root였으므로 실행 위치·계정을 수정했다.

Rocky root에서:

```bash
ssh-copy-id student@192.168.120.129
```

Ubuntu student 비밀번호 입력 후 `Number of key(s) added: 1` 확인.
Ubuntu student에서 확인:

```bash
cd ~/.ssh
cat authorized_keys
```

Rocky의 공개키와 동일한 키가 등록된 것을 확인했다. 끝의 `root@rocky10`은 설명 문자열이며 Ubuntu root 로그인 의미가 아니다. 이 방향은 키 등록까지 출력으로 검증되었고, 비밀번호 없는 로그인 과정의 별도 출력은 없었다.

### 3. Rocky SSH 포트를 220으로 변경

관리 작업은 Rocky root 또는 sudo 권한이 있는 사용자로 수행한다. 접속 계정은 student여도 된다. 명령은 어느 작업 디렉터리에서도 실행 가능하다.

실제 실행:

```bash
semanage port -a -t ssh_port_t -p tcp 220
firewall-cmd --add-port=220/tcp
firewall-cmd --add-port=220/tcp --permanent
vi /etc/ssh/sshd_config
```

파일 설정:

```text
Port 220
```

```bash
/usr/sbin/sshd -t
systemctl restart sshd
ss -nltp | grep ':220'
```

SELinux 명령은 `Port tcp/220 already defined, modifying instead`를 출력했다. 방화벽은 두 번 모두 success. 문법 검사는 출력 없이 통과했고, sshd가 IPv4/IPv6 220번에서 LISTEN하는 것을 확인했다.

Ubuntu에서:

```bash
ssh -p 220 student@192.168.120.128
```

새 주소·포트 조합의 호스트 키 확인에 yes를 입력하고 Rocky student 비밀번호를 입력하여 로그인 성공(Last login 출력).
서버의 호스트 키 안내와 사용자의 공개키 인증은 서로 다른 절차다.

강사 명령과 비교한 간단한 구성은 영구 방화벽 규칙 추가 후 reload하는 방식이다.

```bash
firewall-cmd --add-port=220/tcp --permanent
firewall-cmd --reload
```

현재 설정+영구 설정에 각각 추가한 방식과 목적은 같다. SELinux·방화벽을 먼저 설정하고 문법 검사 후 재시작하면 중간 실패를 줄일 수 있다. 문서의 긴 대시 `–` 대신 실제 명령에는 `--`를 쓴다.

### 4. Ubuntu root → Rocky student 별칭·공개키 접속

Ubuntu root에서 실행한 ssh-copy-id가 다음 오류로 중단되었다.

```text
/root/.ssh/config line 5: no argument after keyword "identityfile~/.ssh/id_rsa"
```

`IdentityFile`과 경로 사이의 공백 누락이 원인이다.

```bash
vi /root/.ssh/config
```

안내한 별칭 설정 예시(수정된 파일 전체는 별도 제출되지 않음):

```sshconfig
Host s1
    HostName 192.168.120.128
    User student
    Port 220
    IdentityFile ~/.ssh/id_rsa
```

수정 후 실제 실행:

```bash
ssh-copy-id student@s1
ssh s1
```

공개키 원본 `/root/.ssh/id_rsa.pub` 확인, Rocky student 비밀번호로 키 1개 등록. 이어 `ssh s1`에서 계정 비밀번호 입력 없이 Last login 화면이 출력되어 접속 성공.
Ubuntu root의 키 생성 로그는 제출되지 않았지만 이 시점의 공개키 존재는 ssh-copy-id 출력으로 확인된다.

| 조회 명령 | con cho 문의 | `nmcli con show ens160` 사용 | 안내 |
| IP 변경 | mynet 활성화 후 10.0.0.10 사라짐 | 임시 주소가 새 프로필에 없음. `+ipv4.addresses`로 추가 후 활성화 | 두 주소·파일 address2·ping 확인 |
| 라우팅 | Windows → Ubuntu ping 시간 초과 | Ubuntu 반환 경로가 .2로 향함. Rocky 10.0.0.10 경유 경로 추가 | ping 성공 |
| 인터페이스 | IF 번호 선택 혼동 | Rocky와 연결된 VMnet8의 Windows 번호 6 사용 | 기존 명령이 맞았음 |

## 기록 상태

- 오후 실습 명령·검증 결과·개념 설명 저장 완료.
- IP 변경 항목 및 트러블슈팅을 별도로 구분했다.
- 스크린샷은 대화에서 읽은 내용을 반영했으며 이미지 원본 파일은 이 문서에 첨부하지 않았다.
- Netplan 최종 적용 결과, 일부 주소 복구 명령, ip_forward 변경 출력 등 미제공 결과는 성공으로 단정하지 않았다.
