# 2026년 9월 10일 오전 실습

## 1. 실습 환경

| 서버 | 인터페이스 | 기존 IPv4 | 추가 IPv4 |
|---|---|---|---|
| Rocky Linux | ens160 | 192.168.120.128/24 | 10.0.0.10/24 |
| Ubuntu | ens160 | 192.168.120.129/24 | 10.0.0.11/24 |

- Ubuntu에서 `s1:82`로 Rocky 웹 서버에 접속 성공. s1의 이름 해석 설정 과정은 제공되지 않음.
- Rocky의 docker0 주소: `172.17.0.1/16`.
- 명령과 결과는 제공된 실습 로그를 정리했으며, 중복 출력과 기본 테스트 페이지 HTML 전문은 생략했다.

## 2. SSH 접속 실패와 설정 오타 해결

Rocky에서 Ubuntu로 접속:

```bash
ssh student@192.168.120.129
```

처음에는 `Connection reset by peer`, 다음에는 `Connection refused` 발생.
Rocky(.128)의 sshd는 정상 실행 중이었으나, 확인해야 할 대상은 Ubuntu(.129)였다.

Ubuntu 콘솔에서 확인:

```bash
systemctl status ssh
/usr/sbin/sshd -t
```

서비스는 failed 상태였으며, 설정 검사에서 다음 오류 확인:

```text
/etc/ssh/sshd_config: line 42: Bad configuration option: PerimitRootLogin
```

해결: `/etc/ssh/sshd_config` 42번째 줄의 `PerimitRootLogin`을 `PermitRootLogin`으로 수정. 옵션 뒤의 값은 변경 대상으로 안내하지 않았다.

```bash
/usr/sbin/sshd -t
systemctl restart ssh
systemctl status ssh
```

- 검사 명령은 `/usr/sbin/sshd -t`가 정확한 경로다. 다른 경로를 입력해 `No such file or directory`가 발생한 과정도 있었다.
- 재시작 후 `active (running)` 확인, Rocky에서 SSH 접속 성공.
- `disabled`는 서비스 자체의 부팅 자동 시작 설정이고, 현재 실행 여부와 별개다. 화면에는 `ssh.socket`도 표시되었다.
- `systemctl enable ssh`는 자동 시작 설정용으로 안내한 명령이며, 실행 여부는 로그로 확인되지 않았다.

## 3. Apache 웹 경로 /www와 SELinux

```bash
vi /etc/httpd/conf/httpd.conf
ls -ld /www
systemctl restart httpd
curl localhost
```

`/www` 권한은 `drwxr-xr-x`, 소유자는 root:root였다. 설정 파일 수정 내용 전문은 제공되지 않았다.
처음 curl 결과는 원하는 페이지 대신 Rocky HTTP Server Test Page였다.

```bash
cat /www/index.html
```

```text
This is www test page..
```

기존 웹 경로의 SELinux 규칙과 파일 타입 확인:

```bash
semanage fcontext -l | grep /var/www
ls -lZ /var/www/html
```

- `/var/www(/.*)?` 기본 타입: `httpd_sys_content_t`.
- `/var/www/html/index.html`과 `index.html.cp`도 `httpd_sys_content_t`였다.
- 로그, CGI, 쓰기 허용 경로 등은 별도 타입을 사용하는 규칙도 출력되었다.

### 명령어 오류 해결

1. 경로에 작은따옴표 대신 백틱을 사용해 셸이 명령 치환을 시도하면서 문법 오류와 `file_spec option is needed for add` 발생.
2. 타입을 `httpd_syscontent_t`로 잘못 입력해 ValueError 발생.
3. 작은따옴표와 정확한 타입 `httpd_sys_content_t`로 수정.

```bash
semanage fcontext -a -t httpd_sys_content_t '/www(/.*)?'
restorecon -RFv /www
ls -lZ /www
curl localhost
```

`semanage fcontext`는 경로에 적용할 규칙을 등록하고, `restorecon`은 그 규칙을 실제 파일에 적용한다.

결과:

```text
/www: default_t → httpd_sys_content_t
/www/index.html: default_t → httpd_sys_content_t
This is www test page..
```

## 4. HTTP 포트 80 → 82 변경과 외부 접속

사용자 확인: `/etc/httpd/conf/httpd.conf` 47번째 줄을 다음과 같이 변경했다.

```apache
Listen 82
```

재시작 및 진단:

```bash
systemctl restart httpd
systemctl status httpd
semanage port -l | grep http
```

- 재시작 실패 로그: `(13)Permission denied`, `no listening sockets available`.
- 당시 `http_port_t` TCP 목록은 `80, 81, 443, 488, 8008, 8009, 8443, 9000`으로, 82가 없었다.
- `grep httpd`는 결과가 없었고 `grep http`로 원하는 포트 타입을 찾았다.

SELinux 허용 포트 등록:

```bash
semanage port -a -t http_port_t -p tcp 82
semanage port -l -C
```

```text
http_port_t    tcp    82
```

이후 Rocky에서 동작 확인:

```bash
curl localhost:82
# This is www test page..
```

포트 등록 이후의 재시작 명령은 제공된 로그에 없지만, 위 응답으로 82번 포트 서비스 동작은 확인했다.

Rocky 방화벽에서 외부 접속 허용:

```bash
firewall-cmd --add-port=82/tcp
firewall-cmd --add-port=82/tcp --permanent
```

두 명령 모두 `success`. 첫 명령은 현재 실행 설정, 두 번째는 영구 설정에 적용한다.

Ubuntu에서 확인:

```bash
curl s1:82
```

첫 시도는 연결 실패, 이후 시도는 `This is www test page..` 출력으로 성공.
SELinux 포트 허용은 httpd의 포트 사용을, 방화벽 개방은 외부 접근을 허용하는 서로 다른 설정이다.

추가 입력 오류:

- `http.conf`로 잘못 입력한 뒤 `httpd.conf`로 수정.
- `systemctl restart`만 입력해 `Too few arguments` 발생 → `systemctl restart httpd`로 수정.
- 붙여넣기 제어문자 `^[[200~`가 포함된 입력도 있었다.

## 5. 사설 IP, 이진수, PAT

### 사설 IPv4 범위

| 범위 | CIDR |
|---|---|
| 10.0.0.0 ~ 10.255.255.255 | 10.0.0.0/8 |
| 172.16.0.0 ~ 172.31.255.255 | 172.16.0.0/12 |
| 192.168.0.0 ~ 192.168.255.255 | 192.168.0.0/16 |

### 8비트 자리 값

```text
2의 지수:  7   6   5   4   3   2   1   0
자리 값: 128  64  32  16   8   4   2   1
```

켜진 비트(1)의 값을 더한다. 192 = 128 + 64 = `11000000`, 168 = 128 + 32 + 8 = `10101000`.
8비트는 0~255를 표현하며, IPv4는 8비트 4묶음으로 총 32비트다.

### 클래스와 참고 그림 내용

| 클래스 | 시작 비트 | 첫 옥텟 범위 | 전통적 네트워크/호스트 비트 |
|---|---|---|---|
| A | 0 | 0~127 | 8 / 24 |
| B | 10 | 128~191 | 16 / 16 |
| C | 110 | 192~223 | 24 / 8 |

A의 0과 127은 특수 용도다. B는 `10000000`(128)부터 `10111111`(191)까지이며, 192는 C에 해당한다.
첨부 그림은 위 클래스별 네트워크/호스트 구분, 사설 주소 범위, Netmask/Subnetmask, Broadcast를 설명했다.
현대 네트워크에서는 클래스보다 CIDR 프리픽스 길이로 네트워크 경계를 판단한다.

참고 그림 원본은 저장 시점에 임시 경로에서 찾지 못해 이미지 파일을 포함하지 못했다. 그림의 핵심 내용은 위 표와 다음 절에 정리했다.

### PAT와 공인 IP 확인

PAT는 여러 내부 연결을 하나의 공인 IP와 포트 번호로 구분하는 NAT 방식이다.

```text
192.168.120.128:50000 → 203.0.113.10:61001
192.168.120.129:50000 → 203.0.113.10:61002
```

위 공인 IP는 설명용이다. 변환 장비가 대응 관계를 기록해 응답을 원래 기기로 전달한다. 포트는 필요에 따라 변경되거나 유지될 수 있다.
방화벽의 `--add-port`는 PAT 설정이 아니다.

실제 실습 출력:

```bash
curl ipconfig.io
# 180.66.125.13
```

이는 당시 외부에서 본 출발지 공인 IP이며, Wi-Fi 주소 자체를 뜻하지 않는다. 이 출력만으로 유선/무선 여부나 구체적인 NAT 구성을 확인할 수는 없다.

## 6. 서브네팅과 슈퍼네팅

### /24를 /25로 서브네팅

호스트 8비트에서 1비트를 네트워크 구분에 사용하면 2개로 나뉜다.
마스크는 `255.255.255.0`에서 `255.255.255.128`로 바뀐다.

| 네트워크 | 할당 가능한 호스트 | 브로드캐스트 |
|---|---|---|
| 192.168.120.0/25 | 192.168.120.1 ~ 192.168.120.126 | 192.168.120.127 |
| 192.168.120.128/25 | 192.168.120.129 ~ 192.168.120.254 | 192.168.120.255 |

현재 실습은 /24이므로 .128을 호스트 주소로 사용할 수 있다. 위처럼 /25로 변경하면 .128은 네트워크 주소가 된다.

### C 클래스 기준 2비트 슈퍼네팅

/24에서 네트워크 비트 2개를 줄이면 /22가 되며, 정렬된 연속 /24 네트워크 4개(2²)를 묶는다.

```text
192.168.120.0/24 ┐
192.168.121.0/24 │
192.168.122.0/24 ├→ 192.168.120.0/22
192.168.123.0/24 ┘

120 = 011110 00
121 = 011110 01
122 = 011110 10
123 = 011110 11
```

- 공통 네트워크 비트: 앞 두 옥텟 16비트 + 세 번째 옥텟 6비트 = 22비트.
- 마스크: `255.255.252.0`.
- 전체 범위: `192.168.120.0 ~ 192.168.123.255`, 총 1,024개 주소.
- /22 경계는 세 번째 옥텟이 4의 배수인 지점이다. 121~124는 하나의 /22로 정확히 묶을 수 없다.
- 이 절은 개념 설명이며 실제 네트워크 마스크 변경 실습은 아니다.

## 7. 인터페이스에 추가 IP 설정 및 통신 확인

Rocky에서 잘못된 명령:

```bash
ip a add 10.0.0.10/24 device ens160
```

```text
Error: either "local" is duplicate, or "device" is garbage.
```

`device`를 `dev`로 수정:

```bash
ip a add 10.0.0.10/24 dev ens160
ip -br a
```

ens160에 기존 `192.168.120.128/24`와 `10.0.0.10/24`가 함께 표시되었다.

Ubuntu에서도 추가:

```bash
ip a add 10.0.0.11/24 dev ens160
ip -br a
ping 10.0.0.10
```

ens160에 기존 `192.168.120.129/24`와 `10.0.0.11/24`가 함께 표시되었다.

```text
9 packets transmitted, 9 received, 0% packet loss
rtt min/avg/max/mdev = 0.656/3.767/12.953/4.764 ms
```

추가한 10.0.0.0/24 대역에서 Ubuntu → Rocky 통신 성공.
`ip a add`는 실행 중인 인터페이스에 적용하는 일시적 설정으로, 재부팅 후 유지하려면 별도 영구 설정이 필요하다.
