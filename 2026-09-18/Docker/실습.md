# Docker — 기존 웹페이지 이미지를 새 Kubernetes 환경으로 옮기기

## 문제와 원인

예전 Docker 실습의 개인 페이지 "This is Sm's home page."를 새 노트북의 Kubernetes에서 실행하려 했다.
새 master1에서 docker images는 빈 목록이었다. 예전 VM의 로컬 이미지는 새 VM으로 자동 이동하지 않는다.
또한 Kubernetes가 사용하는 containerd와 Docker의 이미지 저장소는 별개이므로 docker images가 비어 있다고 Kubernetes 이미지까지 없는 것은 아니다.

Docker Hub 프로필에는 저장소가 표시되지 않았고, 기존 GitHub 기록에도 본인 이미지 push 성공이 확인되지 않았다.
w1의 ImagePullBackOff는 RAM 부족이 아니라 레지스트리에서 해당 이미지를 가져오지 못한 문제였다.

## 원본 확인 — 예전 Rocky 192.168.120.128

사용자는 아래 두 항목이 모두 있다고 확인했다.

- 로컬 이미지 test:nginx, 이미지 ID 4a6b6c1cef36
- /root/docker_class/nginx/의 Dockerfile과 index.html

```bash
hostname
docker images
ls -l /root/docker_class/nginx/
cat /root/docker_class/nginx/index.html
```

이미지 빌드 후 원본 index.html만 수정하면 기존 이미지에는 반영되지 않는다. 최종 컨테이너의 웹 응답으로 내용까지 확인했다.

## 이름 지정·인증·업로드

Rocky에서 진행:

```bash
docker tag test:nginx inche12/test:nginx
docker login -u inche12
docker push inche12/test:nginx
```

Docker Hub를 GitHub 소셜 로그인으로 이용하던 상황이라 Docker Hub Personal Access Token을 비밀번호 대신 사용하도록 안내했다.
push 가능한 쓰기 권한이 필요하다. 토큰은 기록하지 않았다.
사용자가 마지막 nginx: digest: sha256:... 출력을 확인했고 이후 Kubernetes 다운로드와 웹 표시가 성공했다.

| 부분 | 값 |
|---|---|
| 레지스트리 | docker.io |
| 계정/네임스페이스 | inche12 |
| 저장소 | test |
| 태그 | nginx |
| 전체 이미지 이름 | inche12/test:nginx |
| Kubernetes Pod 이름 | lsm — 이미지 이름과 별개 |

## 결과와 구조

```text
예전 Rocky test:nginx
    → tag / push
Docker Hub inche12/test:nginx
    → 새 노트북 w1이 pull
lsm Pod
    → NodePort 30882
브라우저: This is Sm's home page.
```

브라우저 http://192.168.120.150:30882 에서 실제 개인 페이지를 확인했다.
이후 Kubernetes Pod 삭제 실습으로 lsm은 삭제됐으므로 이 주소가 계속 서비스된다고 보장하지 않는다.

## Docker와 Kubernetes 비교

| 목적 | Docker | Kubernetes |
|---|---|---|
| 앱 실행 | docker run | kubectl run으로 Pod 또는 Deployment 생성 |
| 포트 공개 | -p 81:80 | Service(NodePort 등) 구성 |
| 컨테이너 명령 | docker exec | kubectl exec |
| 로컬 이미지 확인 | docker images | 런타임 저장소가 별개일 수 있음 |
| 다른 VM에서 재사용 | 이미지 push/pull 또는 save/load | 노드 런타임이 레지스트리에서 이미지 다운로드 |
