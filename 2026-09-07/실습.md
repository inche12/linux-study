# 2026-09-07 서버 인증 운영 자동화와 디스크

출처: ktcloud-infra-강의노트1.docx의 9/7 기록. 비밀번호·암호 해시는 제외했다. 시스템을 변경하는 예시는 목적별로 확인하며 실행하고, 문서 전체를 스크립트처럼 실행하지 않는다.

## hosts와 sudo

당시 /etc/hosts 예시:

```text
192.168.120.128 ubuntu u1
```

```bash
ssh u1
id
sudo -i
cp /etc/sudoers /root/sudoers.backup
visudo
```

원문은 vi로 sudoers를 편집했으나 정리본은 구문 검사 가능한 visudo를 사용한다. 강의 설정:

```sudoers
%sudo ALL=(ALL:ALL) NOPASSWD: ALL
```

sudo 그룹에 광범위한 비밀번호 없는 실행 권한을 주는 실습이다. 다른 세션에서 `sudo ls /root`로 확인했다. 일반 서비스 계정의 최소 권한 설정 예시는 아니다.

## root 인증과 사용자 생성

Ubuntu에서 잠긴 root 비밀번호 상태를 확인한 뒤 `sudo passwd root`, `su -`로 전환을 시험했다. root 비밀번호 설정 여부와 sudo 사용 가능 여부는 별개다.

```bash
useradd stu1
passwd stu1
id stu1
```

원문은 chpasswd로 비밀번호를 입력하지만 정리본은 실제 값 노출을 피하도록 대화형 passwd 예시로 바꿨다. /etc/shadow 원문 해시는 포함하지 않는다.

## PAM과 로그인 제한

```bash
cd /etc/pam.d
ls
more login
man pam_nologin
```

auth/account/password/session 설정을 살펴보고 `/etc/nologin` 생성 시 일반 사용자 접속 제한, 삭제 후 접속 복구를 확인했다. 적용 결과는 해당 서비스의 PAM 구성에 의존한다. /etc/security의 access.conf, limits.conf, pwquality.conf 등도 확인했다.

## 접속 세션 종료

```bash
who -u
```

원문은 `pkill -9 -t pts/6`으로 특정 터미널 세션을 종료했다. pts/6은 당시 세션이며 다른 환경에서 그대로 실행하면 다른 작업을 종료할 수 있다. 종료 대상을 먼저 식별하는 실험으로 기록한다.

## swap와 부팅 대상

```bash
grep swap /etc/fstab
swapon -s
# 현재 swap 해제: 메모리 여유와 영향을 확인한 뒤 실행
swapoff -a
swapon -s
systemctl list-dependencies graphical.target
systemctl get-default
```

fstab의 swap 행 주석 처리와 현재 swap 해제를 각각 수행했다. 기본 부팅 대상 변경 기록:

```bash
systemctl set-default multi-user.target
```

재부팅 후 텍스트 로그인 환경을 확인했다. service는 서비스, target은 unit 묶음, socket은 소켓 기반 활성화, timer는 예약 실행 등에 쓰인다. Cockpit 웹 관리 화면도 확인했다.

## 시간대와 NTP

```bash
timedatectl set-timezone Asia/Seoul
timedatectl
systemctl status chronyd
timedatectl set-ntp 0
timedatectl set-ntp 1
chronyc tracking
chronyc sources -v
```

NTP 끄기·켜기와 chronyd 상태 변화를 비교했다. 서비스 활성과 실제 동기화 완료는 별도 상태다. 원문에는 즉시 시간 보정 `chronyc makestep`도 포함된다.

Chrony 설정 위치: Rocky `/etc/chrony.conf`, Ubuntu `/etc/chrony/chrony.conf`.

```conf
pool 2.rocky.pool.ntp.org iburst
# 내부 시간 서버를 사용할 클라이언트 예시
# server 192.168.120.130 iburst
# 외부 시간원 없이 자체 시간을 제공하는 실험 설정
local stratum 5
allow 10.0.0.0/24
```

위 줄은 역할별 강의 예시다. local stratum은 자체 시간을 제공하도록 하는 것으로 정확한 외부 시간 동기화를 보장하지 않는다.

## at batch cron timer

```bash
atq
at -l
at -c 2
crontab -l
crontab -e
```

- at: 정해진 시각에 일회 실행. 원문은 shutdown 예약도 실험했다.
- batch: 부하 조건에 따라 일회 작업을 실행. 홈 파일을 tar로 묶는 예시가 있다.
- cron: 반복 작업. 아래는 당시 터미널로 매분 날짜를 출력한 예시다.

```cron
* * * * * date > /dev/pts/1
```

/dev/pts/1은 당시 세션이므로 그대로 재사용하지 않는다. 원문의 core 파일 검색 줄은 출력 리다이렉션이 불명확하여 실행 가능한 명령으로 옮기지 않았다.

```bash
systemctl cat logrotate.timer
ls /etc/logrotate.d
```

```ini
[Timer]
OnCalendar=daily
RandomizedDelaySec=1h
Persistent=true
```

매일 실행, 최대 1시간 임의 지연, 꺼져 있는 동안 놓친 달력 기반 실행 보완 설정을 확인했다. logrotate는 로그 순환을 담당한다.

## 디스크 인식 확인

```bash
lsblk
lsscsi
```

가상 디스크 추가 후 Ubuntu에서 sdb·sdc 각각 1GB 장치가 인식되는 화면을 확인했다. 초기 VMware 설치 설명은 제외하되 이 OS 수준의 확인은 포함했다. 추가 디스크의 파티션 생성·포맷·마운트 완료 기록은 없다.
